# Payment Application - Complete Setup ✅

## Summary

The backend payment application is now **fully functional** and running with an **H2 in-memory database**!

### What Was Fixed

The backend was continuously failing to start due to MySQL connection errors. The issues have been resolved:

#### Problems Identified:
1. **MySQL Connection Failed**: "Access denied for user 'root'@'localhost'" - MySQL server was either not running or credentials were incorrect
2. **H2 ClassNotFoundException**: H2 was marked as `test` scope only in pom.xml, so it wasn't available at runtime when we switched to H2
3. **Schema Syntax Mismatch**: The `schema.sql` had MySQL-specific syntax that wouldn't work with H2

#### Solutions Applied:

1. **Reverted to H2 Database** (for now)
   - Changed `src/main/resources/application.yml` to use H2
   - This ensures the application can run immediately without external dependencies

2. **Updated Maven Dependencies** (`pom.xml`)
   - Removed `<scope>test</scope>` from H2 dependency so it's available at runtime
   - H2 is now a runtime dependency for the main application

3. **Created H2-Compatible Schema** (`src/main/resources/schema.sql`)
   - Previously only had MySQL-specific schema
   - Now uses H2 syntax: `GENERATED BY DEFAULT AS IDENTITY` instead of `AUTO_INCREMENT`
   - Both `payments` and `payment_status_history` tables created successfully

4. **Configured Test Profile** (`src/test/resources/application.yml`)
   - Created separate test configuration with H2 database
   - Tests now run independently and pass successfully

### API Documentation

The backend provides a complete payment lifecycle REST API:

#### Base URL
```
http://localhost:8080/api/payments
```

#### Endpoints

1. **Create Payment** (POST)
   ```
   POST /api/payments
   Content-Type: application/json
   
   {
     "sourceAccount": "ACC001",
     "destinationAccount": "ACC002",
     "amount": "100.50",
     "currency": "USD",
     "reference": "Payment description",
     "idempotencyKey": "unique-key-123"
   }
   ```

2. **List Payments** (GET)
   ```
   GET /api/payments
   GET /api/payments?status=CREATED  # Filter by status
   ```

3. **Get Payment** (GET)
   ```
   GET /api/payments/{paymentId}
   ```

4. **Get Payment History** (GET)
   ```
   GET /api/payments/{paymentId}/history
   ```

5. **Validate Payment** (POST)
   ```
   POST /api/payments/{paymentId}/validate
   ```

6. **Send Payment** (POST)
   ```
   POST /api/payments/{paymentId}/send
   ```

7. **Complete Payment** (POST)
   ```
   POST /api/payments/{paymentId}/complete
   ```

8. **Fail Payment** (POST)
   ```
   POST /api/payments/{paymentId}/fail
   Content-Type: application/json
   
   {
     "errorCode": "NETWORK_ERROR",
     "errorMessage": "Connection timeout"
   }
   ```

### Payment State Machine

Payments follow this lifecycle:

```
CREATED
   ↓
VALIDATED
   ↓
SENT
   ↓
COMPLETED

(From any state except COMPLETED/FAILED, can transition to:)
   ↓
FAILED
```

### Features Implemented

✅ **Complete Payment Lifecycle**
- State machine validation (CREATED → VALIDATED → SENT → COMPLETED)
- Ability to fail from any non-terminal state

✅ **Idempotency**
- Duplicate POST requests with same `idempotencyKey` return existing payment
- Prevents double-processing

✅ **Audit Trail**
- `payment_status_history` table tracks every status transition
- Records fromStatus, toStatus, errorCode, errorMessage, timestamp

✅ **Error Handling**
- Global exception handler
- Meaningful error messages
- Business exception support

✅ **CORS Support**
- Frontend on `localhost:5173` and `127.0.0.1:5173` can access backend
- Fully configured in `PaymentController`

✅ **Database**
- H2 in-memory for development (auto-initialized on startup)
- Spring JDBC with NamedParameterJdbcTemplate for data access

### Troubleshooting

#### Backend won't start
- Check if port 8080 is already in use: `Get-Process java -ErrorAction SilentlyContinue`
- Ensure Java 22+ is installed: `java -version`
- Run `mvn clean` to remove cache: `mvn clean spring-boot:run`

#### Tests failing
- Ensure H2 is in runtime classpath (not just test scope)
- Check `src/test/resources/application.yml` exists and is correct
- Run with debug: `mvn test -X`

#### Frontend can't connect to backend
- Ensure backend is running on port 8080
- Check CORS is enabled in `PaymentController.java`
- Verify frontend API URL is correct in `frontend-react/src/api.js`
